# Web-Larёk

«Web-Larёk» — интернет-магазин, предназначенный для просмотра каталога товаров и оформления покупок. Пользователь может открыть подробную информацию о товаре, добавить его в корзину, выбрать способ оплаты и заполнить данные, необходимые для оформления заказа.

Приложение построено таким образом, чтобы отдельно работать с данными, отображением интерфейса и логикой взаимодействия между ними.

## Архитектура приложения

В основе проекта используется архитектурный подход MVP (Model-View-Presenter). Ответственность распределена между отдельными слоями, благодаря чему работа с данными, интерфейсом и логикой приложения не смешивается в одном месте.

### Model

Model отвечает за состояние приложения. В этом слое хранятся данные товаров, корзины и покупателя, а также выполняются операции над этими данными.

### View

View предназначен для отображения информации пользователю и взаимодействия с DOM-элементами страницы.

### Presenter

Presenter связывает Model и View между собой. Здесь сосредоточена основная логика приложения: обработка пользовательских действий, изменение данных и обновление интерфейса.

## Базовый класс Component

`Component` является базовым классом для компонентов интерфейса.

### Поля класса

`container: HTMLElement` — DOM-элемент, который используется как корневой элемент компонента.

### Методы класса

`render(data?: Partial<T>): HTMLElement` — основной метод компонента. Получает данные для отображения, записывает их в соответствующие свойства и возвращает корневой DOM-элемент.

Предполагается, что классы-наследники будут иметь необходимые сеттеры. При вызове `render` они позволяют передать полученные данные непосредственно в соответствующие элементы интерфейса.

`setImage(element: HTMLImageElement, src: string, alt?: string): void` — вспомогательный метод для настройки изображения: задаёт источник и альтернативный текст элемента `<img>`.

## Класс Api

`Api` содержит общую реализацию для выполнения HTTP-запросов к серверу.

### Конструктор

`constructor(baseUrl: string, options: RequestInit = {})` — получает базовый URL сервера и дополнительные параметры запроса. Второй параметр необязательный и по умолчанию является пустым объектом.

### Поля класса

`baseUrl: string` — адрес, относительно которого формируются запросы к серверу.

`options: RequestInit` — параметры, используемые при выполнении запросов, в том числе заголовки.

### Методы

`get(uri: string): Promise<object>` — отправляет GET-запрос по указанному эндпоинту и возвращает результат в виде промиса с объектом ответа.

`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` — отправляет данные на указанный эндпоинт. Данные передаются в теле запроса в формате JSON. По умолчанию используется метод `POST`, однако его можно изменить с помощью третьего аргумента.

`handleResponse(response: Response): Promise<object>` — защищённый метод для обработки ответа сервера. При корректном ответе возвращает полученные данные, а при ошибке отклоняет промис.

### События

`emit<T extends object>(event: string, data?: T): void` — запускает событие с указанным именем. При необходимости вместе с событием можно передать объект данных.

`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` — создаёт функцию-обработчик для указанного события. При её вызове событие запускается с переданными данными и дополнительным контекстом.

# Данные

Для описания основных данных магазина используются сущности товара и покупателя.

## Интерфейс IProduct

`IProduct` описывает товар, который представлен в каталоге магазина.

Товар содержит идентификатор, название, описание, изображение, категорию и стоимость.

### Поля интерфейса

`id: string` — уникальный идентификатор товара.

`title: string` — название товара, отображаемое в каталоге, карточках и корзине.

`description: string` — текст с подробным описанием товара.

`image: string` — адрес изображения, используемого для отображения товара.

`category: string` — категория, к которой относится товар.

`price: number | null` — стоимость товара. Значение `null` используется, если цена отсутствует или недоступна.

## Интерфейс IBuyer

`IBuyer` содержит сведения о покупателе, которые необходимы для оформления заказа.

В интерфейсе описываются способ оплаты, адрес доставки и контактная информация.

### Поля интерфейса

`payment: TPayment` — выбранный покупателем способ оплаты. Возможные значения ограничиваются типом `TPayment`.

`address: string` — адрес, по которому необходимо доставить заказ.

`email: string` — электронный адрес покупателя для связи и отправки информации о заказе.

`phone: string` — номер телефона, необходимый для связи с покупателем.

## Тип TPayment

`type TPayment = 'card' | 'cash' | ''`

Тип `TPayment` ограничивает набор допустимых значений для поля `payment`. Покупатель может выбрать оплату картой или наличными. Пустая строка используется как начальное значение, когда способ оплаты ещё не выбран.

# Модели данных

## Класс ProductCatalog

`ProductCatalog` отвечает за хранение каталога товаров и выбранного пользователем товара.

Класс позволяет загрузить список товаров, получить весь каталог, найти конкретный товар и сохранить товар, который должен быть показан в подробном представлении.

### Конструктор

`constructor()` — создаёт пустой каталог и устанавливает начальное значение для выбранного товара.

### Поля класса

`protected products: IProduct[]` — массив товаров, загруженных в каталог.

`protected selectedProduct: IProduct | null` — товар, выбранный для просмотра подробной информации. Если товар не выбран, значение равно `null`.

### Методы

`saveProducts(products: IProduct[]): void` — заменяет текущий список товаров полученным массивом.

`getProducts(): IProduct[]` — возвращает все товары, которые находятся в каталоге.

`getProductByID(id: string): IProduct | undefined` — выполняет поиск товара по идентификатору. Если подходящий товар не найден, возвращается `undefined`.

`saveProduct(product: IProduct | null): void` — сохраняет товар, выбранный для подробного просмотра.

`getProduct(): IProduct | null` — возвращает ранее выбранный товар.

## Класс ShoppingCart

`ShoppingCart` предназначен для управления содержимым корзины. С его помощью можно добавлять и удалять товары, очищать корзину, получать количество позиций и общую стоимость, а также проверять, находится ли конкретный товар в корзине.

### Конструктор

`constructor()` — создаёт пустой массив выбранных товаров.

### Поля класса

`protected selectedProducts: IProduct[]` — массив товаров, добавленных пользователем в корзину.

### Методы

`getSelectedProducts(): IProduct[]` — возвращает список товаров, находящихся в корзине.

`addSelectedProduct(product: IProduct): void` — добавляет переданный товар в корзину.

`deleteSelectedProduct(id: string): void` — удаляет товар с указанным идентификатором из корзины.

`clearShoppingCart(): void` — полностью очищает содержимое корзины.

`getTotal(): number` — рассчитывает общую стоимость товаров в корзине. Если корзина пуста либо у товара отсутствует цена, такие значения не увеличивают итоговую сумму.

`getSelectedProductsAmount(): number` — возвращает количество товаров в корзине.

`checkSelectedProduct(id: string): boolean` — определяет, присутствует ли товар с переданным идентификатором в корзине. Результатом является `true` или `false`.

## Класс Buyer

`Buyer` управляет информацией, которую пользователь указывает при оформлении заказа.

Класс хранит выбранный способ оплаты, адрес доставки, email и телефон. Кроме сохранения и получения данных, он выполняет их проверку перед оформлением заказа.

### Конструктор

`constructor()` — создаёт объект с начальными пустыми значениями всех данных покупателя.

### Поля класса

`protected data: IBuyer` — объект, содержащий текущие данные покупателя.

### Методы

`savePaymentType(payment: TPayment): void` — сохраняет выбранный способ оплаты.

`saveAddress(address: string): void` — записывает адрес доставки в данные покупателя.

`saveEmail(email: string): void` — сохраняет указанный адрес электронной почты.

`savePhone(phone: string): void` — сохраняет номер телефона.

`getData(): IBuyer` — возвращает полный набор сохранённых данных покупателя.

`clearBuyerData(): void` — очищает данные покупателя и возвращает всем полям исходные значения.

`validate(): TErrors` — проверяет заполнение всех обязательных полей покупателя. Для каждого свойства возвращается строка с сообщением об ошибке либо пустая строка, если проверка пройдена успешно.

При проверке из начала и конца значения удаляются пробелы. Поэтому строка, состоящая только из пробелов, считается незаполненной.

# Слой коммуникации

## Класс ServerApi

`ServerApi` отвечает за взаимодействие приложения с сервером. Класс использует объект `Api` для выполнения запросов и предоставляет приложению методы, соответствующие необходимым операциям с сервером.

### Конструктор

`constructor(api: IApi)` — принимает объект, реализующий интерфейс `IApi`, через который выполняются запросы.

### Поля класса

`protected api: IApi` — экземпляр API-клиента, используемый для отправки запросов.

### Методы

`getProducts(): Promise<IResult>` — отправляет GET-запрос к эндпоинту `/product/` и получает данные каталога товаров вместе с общей информацией о результате.

`postOrder(orderRequest: IOrderRequest): Promise<IOrderResponse>` — отправляет данные оформляемого заказа на эндпоинт `/order/` и возвращает результат обработки заказа сервером.
